# Peer Review — Story 00000030: Implement 10x10 board

## Summary

The branch adds **Clash** — a 10x10 `asymmetric_100` board and a 20-piece
`standard_clash` army — as a third playable game alongside Battle and
Skirmish, promotes `BOARD_LAYOUT`/`ARMY_COMPOSITION` to real rule flags, moves
the resolved board and roster off `Edition` onto `RuleConfiguration`, adds a
`games.ts` catalog that the picker and reviewer key off, and teaches
`readRecord` to review a record on a board derived from its own position
block. All eleven steps are committed, the README is updated, and no existing
record fixture, sample file, tag string or position block was edited (verified
against the diff: `doc/samples/` gains only the new Clash sample plus a README
entry, and no removed line anywhere in the diff contains a tag or
position-block string).

Verification from the repository root: **`npm run typecheck` — clean**;
**`npm run lint` — clean**; **`npm test` — clean (33 files, 875 tests
passed)**. For completeness the plan's other two gating checks were also run:
`npm run build` is clean, but **`npm run format:check` fails** on
`implementation-plan.md` (comment #4 below).

Spot checks against the brief's areas of particular attention: the Step 4
refactor is complete — no production call site re-resolves a layout or roster
(`BOARD_LAYOUTS`/`ARMY_COMPOSITIONS` are read only by `configureRules` and
`combinationFits`), and `Edition.boardLayout`/`army` are gone; Decision 2's
`TOWER_PLACEMENT` asymmetry is documented at both read sites
(`placementSession.ts`'s header, `buildInitialGameState`'s doc comment); the
derived layout cannot leak into a `RuleConfiguration` (`configureRules` only
looks up `BOARD_LAYOUTS`, and `ReviewScreen` renders from `readRecord`'s
separate `boardLayout` field); `homeRowsPerSide: 0`/`hasBuffer: false` holds —
no review-path reader touches either field; Decision 11's omission rule is
implemented in `reviewedGameLine` and covered by tests. Two problems were
found in the Decision 8/9 reading path, both reproduced by running the real
`readRecord` (comments #1 and #2).
