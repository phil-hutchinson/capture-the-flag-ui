# Peer Review — Story 00000021: Give the computer a real search (MCTS)

## Summary

This branch replaces the computer's single raw-policy sample with a genuine
PUCT Monte-Carlo tree search: a pure search core (`search.ts`), a pure
tree-retaining/budget-capping driver (`searchDriver.ts`), a Web Worker host
(`searchWorker.ts`) and main-thread proxy (`searchClient.ts`), an
easy/medium/hard setup choice (`difficulty.ts`, `EngineSideChoice.tsx`), and
the play-loop wiring in `EngineGame.tsx`, with the old raw-policy
`enginePlayer.ts` removed. Verification is green:
`npm run typecheck` passes, `npm run lint` passes, and `npm test` passes (494
tests, 29 files). The search correctness (PUCT selection, perspective
sign-flipping, terminal handling, legal-only expansion, softmax priors,
most-visited selection), the tree retention/`min(B, max(0, 2·B − R))`
arithmetic, the commit-only-on-confirm contract, and the worker message
protocol all appear correct on inspection; the two findings below are
robustness/cleanliness items, not correctness bugs in the happy path. The
implementation plan did include a dedicated README-accuracy step (Step 8),
which was carried out, so no comment is raised on that front.
