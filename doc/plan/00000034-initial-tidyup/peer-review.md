# Peer Review — Story 00000034: Initial tidyup before showing the app to people

## Summary

The branch adds `src/featureVisibility.ts` (three `boolean`-annotated `SHOW_*`
constants, all `false`) and `src/app/startScreenChoices.ts` (the four start
screen choices as React-free data plus a pure, order-preserving filter),
rewrites `StartScreen.tsx` as a thin renderer over the filtered catalog, gates
the developer game-record disclosure inside `GameRecord.tsx`, makes the four
copy edits in place, flips `DEFAULT_FLIP_BETWEEN_TURNS` to `false`, and brings
`README.md` in line with what a viewer can now reach. The story's governing
constraint holds up: nothing is deleted, all four choices and both hidden
screens stay wired, the `aria-disabled` + `aria-describedby` + no-op-`onClick`
treatment survives intact in the hidden branch, `STORAGE_KEY` is untouched, the
dev-build `console.log` still runs before `GameRecord`'s early return, both
`GameRecord` call sites are untouched, and no test asserts the current value of
a `featureVisibility.ts` constant. All four player-facing copy strings match
`story.md` byte for byte, and the plan does include a README step (Step 7).

`npm run typecheck` — **clean**. `npm run lint` — **clean**. `npm test` —
**clean** (36 files, 959 tests passed). `npm run format:check` and
`npm run build` were also run and are clean. Findings below are all Minor:
comment/documentation staleness, a couple of test-strength gaps, one latent
DOM-id coupling in the new descriptor-driven markup, and two small
presentation/inefficiency points.
