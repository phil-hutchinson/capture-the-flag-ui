# Peer Review — Story 00000025: Add tower restriction

## Summary

This branch adopts the companion project's `2-1:SKIRMISH` edition: `edition.ts`
gains a `TOWER_PLACEMENT` variant and an `active`/`superseded` status, the
registry widens to three editions (with `playableEditions()` now the deliberate
subset the picker enumerates), `board.ts` derives the closed squares purely from
the layout geometry, and `placement.ts` threads the variant through
`PlacementState` into auto-fill, a structured legality result, and a drop-time
refusal query, which `HotSeatGame`/`PlacementStatus`/`Board` surface as a
refusal, a hint, a confirm-time block and a quiet board marking. Records, the
picker default, the sample `2-0:SKIRMISH` fixture and the player-facing copy
(picker + README) all follow. I checked the implementation against the companion
repository's `doc/ruleset/rules.md` (§3, Appendix A's `TOWER_PLACEMENT`, Appendix
B, the glossary's "lane") rather than the plan's paraphrase: the geometric
closed-square definition, the three editions' variant values and statuses, the
independent minors, and the "replay never checks placement" guarantee all match
the source of truth.

Verification from the repository root: `npm run typecheck` **passes**,
`npm run lint` **passes**, `npm test` **passes** (614 tests, 29 files).
`npm run format:check` is also clean. All seven plan steps are committed, each
step's Notes record its deviations, and Step 7 explicitly includes the
`README.md` review the pipeline requires — so no finding is raised for a missing
README step. No Critical or Major findings; the story looks delivered as
specified, with nine Minor items below (mostly documentation drift, copy
consistency and test coverage).
