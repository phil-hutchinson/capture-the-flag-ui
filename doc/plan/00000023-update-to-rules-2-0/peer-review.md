# Peer Review — Story 00000023: Update to rules 2.0

## Summary

This branch replaces the major-1 rule code with a single, edition-parametric
major-2 engine (`src/rules/primary/v2/`), adds the `standard_144`/`standard_64`
board layouts and the `standard_battle`/`standard_skirmish` armies, implements
diagonal attacks, adds a Battle/Skirmish picker to the hot-seat flow, flips the
record layer to the edition-id `Ruleset` tag and the extended move notation, and
disables computer play. The rules logic matches the plan's Grounding facts:
diagonal attacks are one square only, attack-only, movable-target-only, and
lake-corner-permissive; both board layouts (12×12 with buffer, 8×8 without) are
correct; the two published editions carry the right ids and rosters.

Verification from the repository root: `npm run typecheck` **passes**,
`npm run lint` **passes**, `npm test` **passes** (28 files, 561 tests). The plan
includes a dedicated README/documentation check (Step 11), and `README.md` was
in fact updated on this branch, so no comment is raised on that point. The
findings below are mostly design/documentation discrepancies rather than
functional defects; no correctness bug was found in the rules themselves.

Both mid-story owner scope decisions (extended notation brought in as Step 8a;
Gate E's placement-by-keyboard portion waived) are recorded in the documents, as
are the Gate B and Gate D defect fixes, and both fixes look complete rather than
symptom-patched: every live `legalAttacks`/`legalDestinations`/`allSquares`/
`resolveCombat`/`computeOutcome` call site is layout-threaded, and every live
`FullBoard`/`Board` call site passes an explicit layout.

**Round 2 (2026-08-02).** Re-verified after the two fix commits (`643d8a9`
documentation findings, `02a7b50` required edition/layout): `npm run typecheck`
**passes**, `npm run lint` **passes**, `npm test` **passes** (28 files, 561
tests), and `npx prettier --check .` is now clean (finding #7). Comments #1,
#6, #9, #11 and #14 are confirmed fixed as recorded, and #2's core - `edition`
required on `InitialGameState`/`PlayState` and `layout` required on
`Board`/`FullBoard`/`parseRecordFile`/`emptyPlacement`, with every live call
site passing explicitly and the dead `?? BATTLE_LAYOUT` fallbacks removed - is
in place. Two Fixed comments are only partly delivered (#2 leaves three
Battle-defaulting APIs behind, #5 leaves six `describe` titles on the retired
ruleset); those are filed below as #15 and #16 rather than reopened, along with
two findings on the fix commits themselves. No new correctness defect was found
in the rules, and no behaviour change was introduced by either fix commit.

All four round-2 findings (#15-#18) were then fixed; see their Resolution
column. One of them, #17, changes runtime behaviour (the last-played game now
survives a return to the start screen) and this repository has no component
tests, so it is the one item worth confirming by hand at the next manual pass.
